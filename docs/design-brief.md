CREATIVE DIRECTION (unchanged from v3 — read first, still overrides default instincts) Savora is not a restaurant website. It is a luxury food journal brought to life on screen. The site is not "sections" — it's editorial scenes. Each viewport is a different spread in a premium print magazine. Every scene must look visually distinct from the one before it. If two adjacent sections share the same structural logic, redesign one. Typography is the primary structural element, not decoration. Test: if you saw a screenshot of the homepage with the logo removed, could a senior designer still identify it as Savora — not a generic restaurant template? Every layout decision must serve one of these three feelings: Warmth and craft before the food arrives The sense that this place has a point of view and holds it Effortlessness of ordering — elegant, never clinical Spatial rules Don't center everything — left-aligned, asymmetric compositions are the default. Vary container width per section: full-bleed, narrow column, deliberate overflow. Vary vertical spacing intentionally — some sections dense, some airy. No two adjacent sections may share the same compositional structure. Use tension: offset content against edges, oversized type breaking grid, overlapping elements, cropped shapes at viewport edge. Before designing any section, answer in order: What's the structural skeleton of this section (not the content)? Does that skeleton differ from the section before it? Is type the primary visual element, or subordinated to a card/box? Does this look designed by a person, or assembled from a layout system? Remove the logo — does it still feel like one coherent brand? What's the motion/transition on entry, and how does this section behave empty, loading, or in error? If #2 is "no" or #4 is "layout system" — redesign before finalizing the frame. Explicitly avoid Standard template flow, repetitive 3-across grids, generic feature blocks, generic centered hero, stock dashboard look, overused gradients, AI-landing-page feel, generic spinners/skeletons, silent failure states, generic error copy ("Oops!", "Error 404").

5.3 Grid system This is the structural skeleton underneath the asymmetric compositions — without it "intentional asymmetry" degrades into inconsistent guesswork across screens.
Desktop (1440px frame, 1280px max content width, centered): 12-column grid, 24px column gutter, 5vw outer margin (matches the global gutter spec) Asymmetric sections compose in column-span fractions of the 12, never arbitrary pixel splits: Chef's Picks (3:2 feel) → dominant item spans 7 cols, stacked pair spans 5 cols Our Story (55/45 feel) → text spans 7 cols, visual+quote spans 5 cols Reservation split → 6 cols / 6 cols (equal, as specified) Full-bleed sections (dark interstitial, hero atmosphere) ignore the 1280px cap and run to viewport edge, but internal text still aligns to the same 12-col grid overlaid on the full width Baseline grid: 8px vertical rhythm underlies all spacing values (72px, 28px, 20px, 12px are all multiples of 4, snapped to the nearest 8px increment where possible)
Tablet (1024px frame): 8-column grid, 20px gutter, clamp(20px, 4vw, 40px) outer margin Category grid 2×4 = 2 columns of 4 spanning 4 cols each Chef's Picks: dominant item full-width (8 cols), two smaller items 4 cols each side-by-side
Mobile (390px frame): 4-column grid, 16px gutter, 20px outer margin Effectively single-column for most content; the 4-col grid exists for aligning smaller paired elements (icon+label rows, stat pairs) not for asymmetric composition
Spacing tokens (see 5.6 for naming convention): All spacing must resolve to this scale — no arbitrary values outside it: 4, 8, 12, 16, 20, 24, 28, 32, 40, 48, 60, 72, 96px.
5.4 Icon system Style: single-weight line icons, 1.5px stroke, rounded joins, no fills except for active/selected states (which invert to solid) Source: use Lucide (open, matches the restrained editorial feel) as the base set; any icon not in Lucide is custom-drawn to match 1.5px stroke weight and 2px corner radius Sizes: 16px (inline with 13–15px body text), 20px (nav/UI icons — search, heart, cart), 24px (dietary/allergen row uses 14px per v3 spec — kept as an intentional exception for visual quietness) Color: inherits text color of context (dark on light bg, cream on dark bg); active/selected state uses accent red Touch target: icon itself may be 16–24px, but tappable hit area is always 44×44px minimum (per accessibility spec) — pad invisibly, don't enlarge the icon to hit the target Timeline/stage markers: exception — these use Cormorant numerals (1, 2, 3...) not icons, per the order tracking spec
5.5 Asset & export spec Photography: all dish/atmosphere photography exported at 3 densities (@1x, @2x, @3x) in WebP with JPEG fallback; source resolution minimum 2400px on the long edge before any crop Aspect ratios: menu card 4:5, Chef's Picks dominant item 16:10, Chef's Picks stacked pair 4:3, Our Story visual 3:4, gift card product shot 3:2 Compression target: WebP quality 80, aim <200KB per image at @2x for hero/atmosphere shots, <80KB for card thumbnails User-generated/uploaded content (gift card personal message preview, review photos): no fixed aspect ratio assumed — design a center-cropped container with a visible crop-frame preview at upload time, never silently stretch Logo: SVG only, no raster fallback needed at any breakpoint; export a monochrome (cream) and monochrome (dark) variant for use over photography where the two-tone red-A treatment would fail contrast Icons: exported as SVG component instances in Figma, not raster
